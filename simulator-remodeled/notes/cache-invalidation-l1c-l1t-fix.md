# L1C (constant) and L1T (texture) caches never invalidated at kernel boundaries — found and fixed

General simulator-correctness bug. Found while investigating decode-kernel cache stats on the Qwen3-14B
trace (companion investigation: `decode-attn-qwen3-8b-14b-correlation.md`), but the bug itself is generic —
not specific to one kernel or workload.

| Item | Value |
|---|---|
| Symptom | `L1C_this_kernel_cache_misses = 0` for kernel 2633 in a multi-kernel run — suspicious for a cache access that should include real compulsory misses |
| Root cause | `ldst_unit_sm::invalidate()` (the redesigned SM's load/store unit, used whenever `-is_SM_remodeling_enabled 1`, which `SM90_H100` always sets) only ever called `m_L1D->invalidate()`. `m_L1C` (constant cache) and `m_L1T` (texture cache) were never invalidated at any kernel boundary, so they silently accumulated state across the entire process lifetime, indefinitely — by contrast, L1D and L1I (instruction cache) *were* correctly invalidated every kernel boundary. |
| Empirical confirmation | Isolated single-kernel run (`-filter_first_kernel_id 2633 -filter_last_kernel_id 2633`, a genuinely cold process — confirmed via the log's own "Kernel id N is not in the range..." banner showing only kernel 2633 ever launched) showed real, expected compulsory misses across every cache type: L1C 320/960 (33%), L1D 60/460 (13%), L1I 40/40 (100%), L1T 160/160 (100%). A multi-kernel run that also reached kernel 2633 showed `L1C_this_kernel_cache_misses = 0` for the exact same kernel — proof that L1C's state was being inherited from *every prior kernel since process start*, not generated by kernel 2633 itself. |
| Fix | Added `tex_cache::invalidate()` — didn't exist at all before (`tex_cache` only had a tag array and no invalidate/flush method). Wired `m_L1C->invalidate()` and `m_L1T->invalidate()` into both `ldst_unit_sm::invalidate()` and `ldst_unit_sm::flush()`. For `flush()`, used `invalidate()` rather than adding a separate `flush()` to `tex_cache`, since L1C/L1T are read-only (kernels never write constant/texture memory) and therefore can never have a dirty line — a real flush on them would always be a no-op, so invalidate is the only operation that does anything. |
| Side fix required just to build | The legacy (non-remodeled) `ldst_unit::flush()/invalidate()` in `shader.cc` referenced `m_L0I`/`m_L1I` — members that don't exist on `ldst_unit` at all (they belong to the enclosing `shader_core_ctx`) — and called `tex_cache::flush()`, which didn't exist either. This was dead, never-actually-compiled code left over from an earlier uncommitted edit (confirmed via `git diff`: those exact lines were uncommitted `+` additions, not part of any prior commit). Fixed to compile against the real members (`m_L1T->invalidate()` instead of a nonexistent `->flush()`, dropped the `m_L0I`/`m_L1I` lines). This path is never exercised at runtime for `SM90_H100` (`is_SM_remodeling_enabled=1` always selects `SM`/`ldst_unit_sm`, never the legacy `ldst_unit`), but C++ still requires it to compile. |
| Scope of impact | Affects **any** kernel/workload that uses literal PTX constant memory (`const_space`) or texture/surface loads (`tex_space`/`surf_space`) across a multi-kernel run — not specific to decode or to Qwen3-14B. GGML/llama.cpp's `LDG.E.*.CONSTANT` instructions (read-only-hint *global* loads) are **not** affected by this bug: those route through `global_space` → L1D, which was already being invalidated correctly. The bug only matters for genuine `const_space`/`tex_space` accesses. |
| Status | Code fixed, full rebuild verified clean (`accel-sim.out` relinked with no errors). **Re-validation rerun — confirming L1C/L1T now show consistent, cold-start-equivalent miss rates regardless of how many prior kernels ran in the same process — not yet done.** |

## Files changed

- `gpu-simulator/gpgpu-sim/src/gpgpu-sim/gpu-cache.h` — added `tex_cache::invalidate() { m_tags.invalidate(); }`.
- `gpu-simulator/gpgpu-sim/src/gpgpu-sim/remodeling/ldst_unit_sm.cc` — `invalidate()` and `flush()` now also
  call `m_L1C->invalidate()` / `m_L1T->invalidate()`.
- `gpu-simulator/gpgpu-sim/src/gpgpu-sim/shader.cc` — fixed the unrelated pre-existing compile break in the
  dead legacy `ldst_unit::flush()/invalidate()` path (not used by `SM90_H100`, but had to compile).
